# 어두운 역 — 새 밑바탕: 결정해야 할 것과 직책 전체 (2026-10-21)

지금까지의 빌드(v25)·문서(design_v4~gdd_v7, flow_v2)는 **프로토타입**으로 둔다. 새 밑바탕은 여기서 시작한다.
이 문서는 결정이 아니라 **목록**이다. 리드(사용자)가 직책을 나눈 뒤, 각 직책이 자기 칸을 채운다.

---

## 1. 밑바탕에서 답해야 할 질문 여섯

| # | 질문 | 반드시 답할 것 | 답이 나와야 움직이는 직책 |
|---|---|---|---|
| Q1 | **세계관** — 이 세계는 무엇인가 | 왜 어두운가 · 열차·역·안개·신들의 규칙 · 시간과 지리의 범위 · 세계가 플레이어에게 허용하는 것/금지하는 것 | 스토리, 레벨, 아트 |
| Q2 | **스토리** — 무슨 이야기인가 | 주제 한 문장 · 주인공은 누구이며 무엇을 원하나 · 인물 · 막 구조(시작·전환·끝) · 결말의 가짓수와 조건 | 내러티브, 레벨, 시스템 |
| Q3 | **보여주는 방식** — 스토리를 어떻게 전달하나 | 글/그림/공간/행동 중 무엇이 주 매체인가 · 대화·컷·수첩·환경의 역할 분담 · 선택이 이야기를 바꾸는 범위 · 플레이어가 "읽는" 양의 상한 | 내러티브, UX, 아트 |
| Q4 | **게임성** — 플레이어는 무엇을 하나 | 핵심 루프(1분·10분·한 판) · 핵심 동사(걷다·조사하다·고르다·싸우다…) 3개 이내 · 자원·위험·시간의 구조 · 실패의 뜻 | 게임 디자인, 시스템, 레벨 |
| Q5 | **재미** — 왜 계속 하나 | 긴장 곡선 · 보상(발견·성장·관계·결말) · 반복 플레이 이유 · 장르 참고작 3개와 우리가 다른 점 | 게임 디자인, 프로듀서 |
| Q6 | **보여줄 것** — 화면에 무엇이 있나 | 한 화면의 구성 · 판단에 필요한 정보 vs 숨길 정보 · 톤(색·빛·크기) · 플랫폼(PC 웹) 제약 | UX, 아트, 프로그래밍 |

답하는 순서(제안): 비전 한 문장 → Q1·Q2·Q4 동시 초고 → 서로 맞춰 수정 → Q3·Q5·Q6.

## 2. 직책 전체

### A. 총괄
| 직책 | 하는 일 | 내놓는 것 | 받는 것 |
|---|---|---|---|
| **디렉터(리드)** | 비전 한 문장, 무엇을 만들고 무엇을 안 만들지, 충돌 때 최종 결정, 승인 | 비전 문서, 결정 기록 | 모든 직책의 초고 |
| **프로듀서** | 단계·일정·완료 기준, 범위 자르기, 위험 관리, 문서 정리 | 로드맵, 단계별 체크리스트, 회의록 | 디렉터 결정, 각 직책 진척 |

### B. 기반 설계
| 직책 | 하는 일 | 내놓는 것 | 받는 것 |
|---|---|---|---|
| **세계관 설정(World)** | Q1. 세계 규칙·역사·장소·존재(신·괴물·열차)·금기 | 세계관 바이블(규칙 목록, 지도, 연표, 용어집) | 비전 |
| **스토리 작가(Narrative Writer)** | Q2. 주제·주인공·인물·막·결말, 대사와 장면 글 | 시놉시스, 인물표, 막 구조, 장면 대본 | 세계관 바이블 |
| **내러티브 디자이너(Narrative Design)** | Q3. 이야기를 게임 안에서 어떻게 보여주나 — 대화·컷·수첩·환경·선택 분기 설계, 콘티 | 전달 방식 규칙, 분기도, 장면별 콘티 | 스토리, 게임 디자인 |
| **게임 디자이너(Core/Systems Design)** | Q4·Q5. 핵심 루프, 동사, 메커닉, 긴장 곡선, 재미의 근거 | 게임 디자인 문서(GDD) 핵심 장, 참고작 분석 | 비전, 세계관, 스토리 |
| **시스템·밸런스 디자이너** | 자원·전투·성장·확률의 수치, 시뮬레이션으로 검증 | 수치표, 봇 시뮬 결과, 조정 기록 | GDD |
| **레벨 디자이너** | 공간·동선·발견 배치·원정 구조·랜드마크 | 맵 설계도(손 지도), 배치표, 동선 검증 | 세계관, 스토리, GDD |
| **UX·인터랙션 디자이너** | Q6. 조작·메뉴·창 흐름·정보 가시성·접근성(PC 키보드·마우스) | 화면 구성도, 입력표, 창 흐름도, 가시성 규칙 | GDD, 내러티브 |

### C. 표현
| 직책 | 하는 일 | 내놓는 것 | 받는 것 |
|---|---|---|---|
| **아트 디렉터** | 비주얼 톤, 팔레트, 픽셀 규격(타일·인물·초상·그림 크기), 일러스트 규칙 | 아트 바이블, 규격표, 견본 | 세계관, UX |
| **픽셀·일러스트 아티스트** | 타일·인물·소품·초상·장면 그림 생산(Codex 파이프라인) | 자산 파일, 프롬프트 기록 | 아트 바이블, 레벨 배치표 |
| **UI 아티스트** | 창·아이콘·폰트·커서·HUD 그림 | UI 자산 | UX 구성도, 아트 바이블 |
| **사운드 디자이너** | 효과음·앰비언트·음악(현재 거의 없음) | 사운드 목록, 파일 | 세계관, 장면 콘티 |

### D. 구현·검증
| 직책 | 하는 일 | 내놓는 것 | 받는 것 |
|---|---|---|---|
| **엔진·클라이언트 프로그래머** | 규칙 엔진, 렌더, 입력, 저장, 성능 | 코드, 자동 테스트 | GDD, 수치표, UX |
| **툴·파이프라인** | 아트 변환(sheet/chunky), 빌드, 배포, 디버그 훅 | 도구 스크립트, 배포 절차 | 아트 규격, 프로그래머 |
| **QA** | 테스트 계획, 자동 플레이, 버그·규칙 위반 보고, 회귀 확인 | QA 보고서, 버그 목록 | 빌드, GDD |
| **플레이테스트·시니어 검수** | 실 사용감·가시성·개연성·자연스러움을 플레이어 눈으로 | 검수 보고(문제·근거·제안) | 빌드 |
| **텍스트 에디터(문장 교정)** | 한국어 문장·용어 통일, 길이 상한, 금지 표현 검사 | 교정본, 용어집 반영 | 모든 글 |

## 4. 프로토타입에서 가져갈 수 있는 것 (버리지 않고 창고에)
- 엔진 틀(v2 `dispatch`·시드 난수·자동 테스트·봇 시뮬) — 규칙이 바뀌어도 틀은 재사용 가능.
- PC 화면 틀(640×360 정수 배율, 480×320 지도, 패널·띠·대화상자) — Q6 답에 따라 유지/폐기.
- 아트 파이프라인(Codex → sheet.py/chunky.py → manifest) — 규격만 바꾸면 그대로.
- 자산 약 200점(타일·인물·초상·그림) — 아트 디렉터가 새 톤에 맞는 것만 추린다.
- 공부 문서(docs/pc_ui_outline.md, docs/study_map_story.md) — 직책들의 참고 자료.
- 검수 보고서들 — "이전에 틀렸던 것" 목록으로.
