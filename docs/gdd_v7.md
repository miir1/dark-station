# 어두운 역 — 게임 디자인 문서 v7 초고 (PC 웹게임 판, 2026-10-21)

이 문서는 docs/framework_v6.md(게임 틀 v6.1)의 시스템을 docs/redesign/brief_pc.md(PC 전환 전제)에 맞춰 **한 권으로 다시 짠 초고**다. 전제와 어긋나면 brief_pc.md가 이긴다. 세계관은 docs/redesign/world.md, 콘티는 docs/redesign/storyboard.md가 원본이다.

표기 규칙:
- 숫자 뒤에 아무 표시가 없으면 **엔진(v2/engine.js·data.js)에서 확인한 값**이다.
- **[제안]** = 아직 안 잰 값. 봇이나 사람이 재서 고친다.
- **[비움]** = 초고에서 못 채운 곳. 빈 채로 둔다.
- "논리 px"는 640×360 기준 수치, "화면 px"는 1280×720(배율 2) 기준 수치다. 1080p는 배율 3.

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 한 줄 | 멈춘 2호선의 기관사가, 이름을 세는 안개 아래 지하역에서 여섯 사람과 열흘을 버티고, **누구의 이름을 명부에 남길지** 정한다 |
| 장르 | 운영(A Dark Room) + 사건 카드(서울 2033) + 걸어 다니는 집(쯔꾸르 호러) + 드문 몸의 전투(피어 앤 헝거) |
| 플랫폼 | **1순위 PC 브라우저**(크롬·엣지·파이어폭스, 키보드+마우스). 2순위 폰 가로(터치로 클릭 걷기만). 설치 없음, 서버 없음(정적 파일) |
| 기준 화면 | 1280×720(16:9). 1920×1080은 정수 배율 3. 작은 창은 배율 1(640×360) |
| 길이 | 열흘 = 40~60분. 결정 35~50개. 2·3막은 같은 틀로 다른 역 |
| 대상 | 글 읽는 걸 싫어하지 않는 PC 플레이어. 피어 앤 헝거·서울 2033·A Dark Room을 아는 사람이면 설명 없이 들어온다 |
| 화면에 숫자로 보이는 것 | **식량·물·땔감 셋**(오른쪽 패널). 나머지는 전부 흔적(선로의 물, 계단의 안개, 얼굴, 붕대, 앉은 자세, 분필 벽) |
| 규칙 하나 | **것들은 당신을 세지 않는다.** 당신은 다치지 않고, 그래서 가장 무섭다 |
| 결말 | D1에 당신이 적은 수첩 페이지 위에 구멍과 줄긋기. 점수는 숨긴다 |

폰 세로 판(v3 지금 코드)과 달라지는 것을 한 줄로: **지도와 패널과 대화창이 한 화면에 같이 있고, 마우스를 올리면 판단 정보가 보인다.** 십자키·터치 패드는 없다.

## 2. 화면과 조작

### 2-1. 기준 레이아웃 (1280×720, 배율 2)

```
 x 0                                   960                    1280
 y 0  ┌────────────────────────────────────┬──────────────────────┐
      │                                    │  D3 아침   열차까지 7일│  ← 패널 머리 (0~96)
      │                                    ├──────────────────────┤
      │        지도 상자  960×640          │  🍞 식량  9           │  ← 자원 셋 (96~176)
      │        타일 32×2 = 64px            │  💧 물    7           │     숫자는 이 셋뿐
      │        한 화면 15×10칸             │  🔥 땔감  4  [불 ▮▮▯] │
      │                                    ├──────────────────────┤
      │                                    │ 수첩 │ 명부 │ 시선   │  ← 탭 줄 (176~216)
      │                                    ├──────────────────────┤
 384  │ ┌────────────────────────────────┐ │                      │
      │ │ 대화창 960×256 (지도 아래 1/3) │ │   탭 내용 464px      │  ← (216~680)
      │ │ [초상 192] 이름 / 글 18px 4줄  │ │                      │
 640  │ └────────────────────────────────┘ ├──────────────────────┤
      ├────────────────────────────────────┤ ⚙ 설정 │ ⎘ 코드 │ ⛶ F │  ← 패널 발 (680~720)
 720  │ 목표 한 줄 · 토스트 · 단축키 힌트  │                      │  ← 아래 띠 960×80
      └────────────────────────────────────┴──────────────────────┘
```

| 영역 | 화면 px (720p) | 논리 px | 내용 |
|---|---|---|---|
| 지도 상자 | 0,0 – 960,640 | 480×320 | 타일 32 원본, 배율 2 → 64px. **한 화면 15×10칸**. 지도가 작으면 가운데 정렬, 크면 카메라가 주인공을 따라간다 |
| 아래 띠 | 0,640 – 960,720 | 480×40 | 왼쪽: 목표 한 줄(14px 금색, 지금 `#goal`). 가운데: 토스트(16px). 오른쪽: 단축키 힌트("Space 조사 · Tab 수첩 · F 전체 화면", 14px 회색) |
| 패널 | 960,0 – 1280,720 | 160×360 | 머리 / 자원 셋 / 탭 줄 / 탭 내용 / 발 (2-4) |
| 대화창 | 0,384 – 960,640 (지도 위 덮음) | 480×128 | 초상 192 왼쪽 + 이름 14px 금색 + 글 18px 세리프 4줄. 지도 위 2/3는 35% 어두워진 채 보인다 |
| 선택지 상자 | 대화창 바로 위, 오른쪽 정렬, 480×(16+40n) | 240×(8+20n) | 번호 1~4 + 아이콘 24 + 행동 18px + 보조 14px 회색. 2-5 |

**브리프의 "20×11칸"에 대해.** 타일 32 × 배율 2 = 64px이므로 960px 폭에는 15칸, 640px 높이에는 10칸이 든다. 20×11은 지도가 1280×704 전체를 쓸 때의 수다. 이 문서는 **15×10칸**으로 쓴다(RPG Maker VX/MV의 17×13과 같은 감각). 패널을 지도 위에 반투명으로 띄우면 20×11이 되지만 "지도와 패널을 동시에"라는 전제가 약해진다 → 디자이너가 묻는 것 1.

### 2-2. 배율과 창 크기

| 상황 | 규칙 |
|---|---|
| 배율 계산 | `s = clamp(floor(min(창 너비/640, 창 높이/360)), 1, 4)`. 정수만. 1280×720 → 2, 1920×1080 → 3, 2560×1440 → 4 |
| 레이아웃 | 논리 640×360을 s배로 키워 **창 가운데**에 놓는다. 남는 곳은 검정(레터박스). 지도·패널·대화창 전부 같은 배율 |
| 배율 1 (창이 1280×720 미만) | 640×360으로 떨어진다. 글자는 캔버스가 아니라 DOM이므로 **아래로는 본문 14·대화 15·보조 12까지만** 줄인다 [제안]. 아래 띠에 "창을 키우거나 F로 전체 화면" 안내 |
| 전체 화면 | F 키 또는 패널 발의 ⛶ 버튼 → `requestFullscreen`. 나가면 Esc(브라우저 기본). 전체 화면에서도 배율은 정수 |
| 글자 (720p) | 본문 16 / 대화 18 / 보조 14 / 패널 숫자 24 / 패널 머리 24. 1080p는 ×1.5 (24/27/21/36). 서체는 지금 그대로(Noto Serif KR·바탕) |
| 폰 가로 (2순위) | 844×390 → 배율 1, 레터박스. 터치 = 클릭. 호버 툴팁은 **길게 누르기 400ms**로 대신한다 [제안]. 세로로 들면 "가로로 돌려 주세요" 한 장 |
| 창 비율이 16:9가 아닐 때 | 넓으면 좌우 검정, 높으면 위아래 검정. 지도를 늘리지 않는다 |

### 2-3. 입력표

| 하는 일 | 키보드 | 마우스 | 터치(폰 가로) |
|---|---|---|---|
| 걷기 | 화살표 / WASD (누르고 있으면 계속) | **지도 칸 클릭 → 그 칸까지 걸어간다**(BFS 최단 길, 지금 `pathTo` 재사용). 막힌 칸은 가장 가까운 닿는 칸까지 | 칸 탭 |
| 조사·말 걸기 | Space / Enter / Z (바라보는 칸) | 물건·사람 **클릭** = 옆까지 걸어간 뒤 조사 | 탭 |
| 확인·다음 | Space / Enter / Z | 대화창 클릭 | 탭 |
| 뒤로·메뉴 | Esc / X | 우클릭 | 패널 발 ⚙ |
| 선택지 | **1 ~ 4** 숫자, 위/아래 + Enter | 선택지 클릭 | 탭 |
| 패널 탭 | **Tab** (수첩 → 명부 → 시선 → 닫기 순환) | 탭 클릭 | 탭 |
| 자리 바꾸기(수첩 페이지) | 사람 줄에서 좌/우 = 자리 순환, Enter 확정 | 사람 줄 클릭 → 자리 목록 펼침 → 클릭 | 탭 |
| 전체 화면 | F | ⛶ 버튼 | ⛶ |
| 저장 코드 | Ctrl+S 내보내기 / Ctrl+O 불러오기 [제안] | ⎘ 버튼 | ⎘ |
| 음량 | M 음소거 [제안] | ⚙ 설정 | ⚙ |
| 판단 정보 | 선택지에 커서 두고 **?** [제안] | **마우스 올리기(호버)** 150ms 뒤 툴팁 | 길게 누르기 |

걷는 속도: 한 칸 230ms(지금 `STEP_MS`), 클릭 걷기도 같다. 걷는 도중 다른 칸을 클릭하면 길을 바꾼다. 대화가 열려 있으면 지도 클릭은 무시한다.

### 2-4. 호버 툴팁 — 무엇이 보이나 (판단 정보 목록)

툴팁은 14px 글 상자(검은 판, 뼈색 테두리), 커서 오른쪽 아래, 최대 4줄. **숫자를 쓰지 않는 곳**은 낱말 표(§3-4)대로 흔적 말로 쓴다.

| 올린 것 | 보이는 줄 (위에서부터) |
|---|---|
| 사람 (역) | 이름 · 오늘 자리("물 긷기 → 물 +5") · 얼굴 말("괜찮다 / 지쳐 있다 / 무너질 것 같다" = 스트레스 3단) · 붕대("경상 이틀째 / 중상") · 앉음("피로, 오늘은 원정 못 간다") · 유대 점 ●●○○ · 소원 단계("소원 2/3 — 명단이 필요하다") · 상처 이름 |
| 사람 (고정 셋) | 위와 같되 자리 줄에 "기본 자리: 발전기 — 떼면 전기가 안 켜진다" |
| 화로 | "불: 보통 · 오늘 밤 땔감 −1 · 남은 땔감 4" · "불이 크면 시선이 는다"(D3 뒤) |
| 뜯을 수 있는 물건 | 이름 · **임자**("순례의 게시판") · "뜯으면 땔감 +1" · **사라지는 것 한 줄**("순례의 '못 받은 전화' 이야기가 사라진다") |
| 뜯긴 자리 | "의자가 있던 자리. 오늘 밤부터 둘이 바닥에서 잔다" |
| 발전기 | "전기: 켜짐(기철) · 물 긷기 가능 · 시선 +1" 또는 "침수 5 — 잠김" |
| 선로의 물 / 승강장 웅덩이 | "물이 선로 아랫줄까지" / "승강장에 닿았다 — 발전기가 위험하다"(D5 뒤 '침수' 낱말) |
| 출구 계단 안개 | "안개가 계단 두 칸 아래까지 내려왔다" (숫자 아님, 칸 그림) |
| 분필 벽 | "세로줄 넷" + 실종자 이름이 있으면 그 이름 |
| 잠자리 | "서하의 잠자리" / "비어 있다 — 기철은 돌아오지 않았다" / "개지 않은 채" |
| 무덤 | 이름 · "D6 밤 · 이름을 불러 보냈다" |
| 원정 입구(A·B·C) | 지역 이름 · 오늘 갈 수 있는가 · "짝수 날만" · 남은 층·랜드마크 유무 |
| 수첩 페이지의 자리 | 자리 이름 · **그 사람이 하면 나오는 수**("서하: 식량 +5 · 땔감 +1") · 스트레스 변화 · 열린 날 |
| 선택지 | 행동 · **양쪽 값 전부**(자원 ±, 시선 ±, 스트레스 ±, 확률 %) · 고를 수 없는 이유 · D7 뒤엔 "수첩: …" 힌트 줄 |
| 패널 자원 숫자 | 식량: "하루 4 먹는다. 운임 1/명" · 물: "물 긷기는 전기가 있어야" · 땔감: "화로가 밤마다 1. 역에서 뜯을 수 있는 것 3개 남음" |
| 패널 시선 막대 | 신 이름(들은 뒤에만) · "징조가 가깝다 / 왔다" · 수첩 규칙이 있으면 그 한 줄 |
| 전투 부위 | 부위 이름 · 남은 칸 · 명중 %(관찰·완력 반영) · "부러지면 상처를 굴린다" |

원칙: **판단에 필요한 값은 전부 보여 준다. 결과(주사위)는 숨긴다.** 툴팁은 보이는 정보만 말하고, 내부 수치(스트레스 73, 시선 5)는 말하지 않는다.

| 발 | 680~720 | ⚙ 설정(음량·되감기) · ⎘ 저장 코드 · ⛶ 전체 화면. 아이콘 24 |

패널은 DOM(HTML)이다. 캔버스는 지도 상자뿐. 지금 `#hud`(위 띠)와 `#pad`(아래 패드)는 없어지고 패널이 그 역할을 맡는다.

### 2-6. 장면별 화면 규격

| 장면 | 어디에 | 규격 (화면 px, 720p) |
|---|---|---|
| **대화창** | 지도 상자 아래 1/3 덮음 | 960×256, y 384~640. 안쪽 여백 16. 초상 192×192 왼쪽(원본 96도트 ×2). 이름 14px 금색 자간 넓게. 글 18px 세리프 줄간 1.6, 최대 4줄, 한 글자씩 타자(지금 `.tw`). 오른쪽 아래 ▼ 깜빡임. 장면 그림이 있으면 창 **위**에 768×432(원본 384×216 ×2) 가운데, 초상은 그림 왼쪽 아래 모서리에 겹침 |

### 4-5. 열흘 예산표 (엔진 수 + [제안], 봇으로 재서 고친다)

## 5. 사람·자리

### 5-1. 기본값이 정해진 셋 + 움직이는 셋

| 사람 | 기본 자리 | 반쪽 일(자동) | 비우면 | 엔진 |
|---|---|---|---|---|
| 순례 (관찰 2·완력 1·기술 1·말 2, 알뜰·무릎 약함) | 화로지기 | 역 안 수색 +1 (땔감 풀이 남으면 땔감, 아니면 식량) | 불이 한 단 작아진다 | 새 일 `keeper` [제안] |
| 마리 (기술 2, 간호·불면) | 치료 | 환자 없으면 물 긷기 2 | 치료 없음 | `tend` + 반쪽 `pump` 2 |
| 기철 (기술 3·완력 2, 손재주·완고) | 발전기 | 배수 +1 | 전기가 안 켜진다 — 물 긷기 막힘, 발전기 카드 사라짐 | `gen`(전력 3+1) + 반쪽 `drain` 1 |
| 서하 (관찰 3·기술 2, 눈썰미·겁) | 플레이어 | — | — | 수색 5 · 물 5 |
| 은지 (말 3·관찰 2, 흥정·조급) | 플레이어 | — | — | 수색 4 · 물 4 |
| 동하 (완력 3, 힘꾼·눈치 없음) | 플레이어 | — | — | 수색 3 · 물 4 · 배수 3 · 경계 3 |

산출 공식(엔진): 수색 `round((3+특성)×(0.75+0.25×관찰))` 풀에서, 물 `round(4×(0.75+0.25×기술))` 전력 1, 배수 `floor(2×(0.75+0.25×완력))`, 경계 같은 식으로 시선 −. 기본값은 **바꿀 수 있되 값이 든다**. 엔진의 6명 배치 구조(`plan`, `assign`)는 그대로 두고 '기본값 + 값'만 얹는다. 붕괴·중상이면 자리가 비고 반쪽 일도 멈춘다 → 플레이어가 대신 세운다. 고정 셋에게 **하루 한 번 말 걸기**(수첩 페이지 오른쪽 한 줄, 날마다 바뀜). 비극 전날엔 그 사람 말이 끊긴다.

### 5-2. 자리 6 — 열리는 날

| 자리 | 열림 | 설명 (사람 입으로) | 산출 | 스트레스 |
|---|---|---|---|---|
| 수색 | D1 | 순례: "역 안에 아직 남은 게 있어" | 식량 3~5 **+ 땔감 1**(풀 남으면, 하루 1) | +4 |
| 물 긷기 | D1 | 기철: "전기가 있어야 펌프가 돌아" | 물 4~5 (전력 1) | +4 |
| 휴식 | D1 | — | 스트레스 −16 (의자 뜯으면 −14·−12), 경상 회복 카운터 | −16 |
| 경계 | D3 밤 뒤 | 순례: "경계는 둘이 서야 돼" | 둘이면 시선 −2, 순찰대 맞섬 | +4 |
| 공사 | D4 | 기철: "부품만 있으면" | 진행 +1 (기철 +2) | +5 |

### 5-3. 피로

| 값 | 뜻 | 화면 |
|---|---|---|
| 0 | 갈 수 있다 | 서 있음 |
| 1 | 갈 수 있다 (한 번 더) | 앉아 있음 |
| 2 | **원정 불가** | 앉아서 고개 숙임 |

원정 귀환 +1, 원정 안 간 날 −1. 짝수 날만 원정이므로 같은 둘을 매번 보내도 피로로 막히지 않는다 — 막는 건 피로가 아니라 **남은 한 사람이 역을 못 돌린다**는 것.

### 7-1. 규칙표

### 7-3. 엔진으로 옮기는 상태 기계

지금 v3/battle.js는 `Math.random` + `UI.open` 비동기라 봇이 못 잰다. v7은 **엔진이 상태를 들고, v3는 그리기만** 한다.

상태 `s.battle`:
```
{ foe: 'bonepicker'|'drowned', round: 1, team: [rid, rid],
  hp: {head, body, arm, leg}, max: {...}, telegraph: rid,
  water: 0..6 (익사자), picked: ['arm'] (뼈 줍는 이가 주워 간 것),
  acted: {rid: true}, log: [{text, kind}], result: null|'win'|'lose'|'flee' }
```

| dispatch 액션 | 인자 | 하는 일 | 다음 |
|---|---|---|---|
| `battleStart` | `{ foe }` | 원정 사건에서 "싸운다"를 고르면. 상태 만들고 예고 1명 뽑음(`rand`) | 우리 차례 |
| `battleAct` | `{ rid, act: 'strike'|'guard'|'tool'|'flee', part?, item? }` | 그 사람의 행동 하나. 둘 다 행동하면 자동으로 적 차례 → 라운드 +1, 새 예고 | 우리 차례 또는 끝 |
| `battleNext` | — | 결과 화면 넘김. `result`를 원정 사건 결과로 흘려보냄(지금 `expFight`의 역할 흡수) | 원정 계속 |
| `countStart` | — | 세는 아이 장면 시작. `s.count = { turn: 1, n: 2, seen: 2, sent: [] }` | 셈 1 |
| `countAct` | `{ i: 0|1|2 }` | 숨 죽인다 / 이름을 부른다 / 뒤돌려 보낸다 | 셈 2·3 또는 끝 |

`expFight`(지금, 화면이 결과를 넣어 줌)는 `battleNext`로 대체된다. 봇(`sim/bots.js`)에 `boss: 'fight'|'pay'` 정책이 붙고, 싸울 때는 "예고된 사람 막기 + 나머지 몸 때리기"가 기본 수다.

### 7-4. 세는 아이 — 화면과 조작

규칙: **아이의 수 = 보이는 우리 수(당신 제외)** 여야 한다. 턴마다 아이가 먼저 세고(수가 바뀐다), 우리가 하나 한다. 3턴 뒤 수가 보이는 수와 다르면 **차이만큼 세어진다**(실종, 유대 높은 순). 판정 없음.

아이가 세는 순서 [제안, 고정]:

| 턴 | 아이가 먼저 | 왜 (세계관) | 보이는 수 2일 때 맞는 수 |
|---|---|---|---|
| 1 | +1 → 3 | 당신을 셌다 ("…넷?" 하고 멈칫, 그리고 셋) | 숨 죽인다(3 그대로 — 다음 턴을 기다린다) |
| 2 | −2 → 1 | 둘이 서면 메아리로 흐려진다 | 이름을 부른다 (+1 → 2) |
| 3 | +0 | 아이가 당신을 다시 본다 "…넷?" | 숨 죽인다 (2) |

우리 행동: 숨 죽인다 = 그대로 / 이름을 부른다 = +1 (호 +1, 시선 +1) / 한 사람을 뒤돌려 보낸다 = 아이의 수 −1 **그리고** 보이는 수 −1(그 사람은 E로 돌아간다, 전리품 없음). 둘 다 보내면 0 → "영" → 아이가 사라진다, 배터리 없음.

화면(§2-6): 큰 숫자 96px가 아이의 수, 그 아래 "보이는 우리: 2". 두 번째 판(수첩 열림)엔 2턴 선택지에 "수첩: 둘이 서면 흐려진다"가 미리 붙는다 → 첫 판은 외워야 하고 둘째 판은 안다. 이득은 확신이다.

### 10-3. 점수 (숨김, 봇 평가용)

`score = 탄 비율(0~3) + 이룬 소원(0~3) + 약속(−2~+2)`
