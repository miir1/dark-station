## 1. 비전 한 문장 — 후보 셋

프로토타입이 품고 있던 씨앗: 이름·명부·"것들은 당신을 세지 않는다"·역을 태워 사는 열흘·여섯 사람. 셋 다 이 씨앗에서 나왔지만 **힘을 주는 곳이 다르다.**

| # | 비전 한 문장 | 핵심 동사 | 버리는 것 | 지키는 것 |
|---|---|---|---|---|
| A **생존 관리** | "역을 태워 열흘을 버틴다 — 무엇을 뜯고 누구를 보낼지, 매일 값을 치르는 게임" | 배치하다·보내다·뜯다 | 소원 3단계·비극 대본·막 구조 같은 **정해진 이야기**. 인물은 자원과 성격만 남는다 | 식량·물·땔감 셋, 헐벗는 역, 피로·상처·시선 수지, 봇 합격선, 반복 플레이 |
| B **인물·약속 드라마** | "이름을 적는 사람이 열흘 뒤 누구의 이름을 남길지 정하는 이야기" | 걸어가다·듣다·약속하다 | 자원 종류 절반(부품·약품), 보스 전투, 원정 카드 양산. **숫자는 더 줄어든다** | 여섯 사람 목소리 카드, 소원·비극·손등 구멍, 수첩 결말, D7 방송, 금지어 말투 |
| C **탐험·발견** | "안개 아래 역과 터널을 걸으며 세계의 규칙을 하나씩 알아내는 게임" | 걷다·조사하다·적다 | 하루 5단계 루프·배치표·아침 카드. 열흘 시계는 느슨해진다 | 신=규칙, 수첩 뒷장 이월, 랜드마크 셋·셈 장면, 걷는 동안 보이는 것, 손 지도 |

부디렉터 소견(결정 아님): 검수·QA가 "글은 상품 수준, 플레이는 빈다"고 했다. A는 프로토타입의 약점(결정 없음)을 정면으로 풀고, B는 강점(글)을 중심에 둔다. C는 가장 새로 짜야 한다. **A와 B 중 하나를 주, 다른 하나를 종**으로 두는 것이 현실적이다.

## 2. 프로토타입 평가 (10줄)

| 작동한 것 (근거) | 밑바탕부터 틀린 것 (근거) |
|---|---|
| 글·분위기·초상·장면 그림 — "이미 상품 수준" (review_senior §잘된 것 1·5) | **하루의 결정이 비어 있다** — 추천 배치 1번 + 원정이면 끝, balanced 봇 60% 승 (review §1, QA 시나리오 8) |
| "판단은 친절하게, 결과는 가혹하게"가 화면에 살아 있다 (review 2) | **결말이 깃발 하나(통로)에 묶임** — stay 봇 정원 0 = 100%, 화면이 안 알려 줌 (QA 상위 1) |
| 엔진 틀(dispatch·시드·테스트 53·봇 200판)이 설계를 **잴 수 있게** 해 준다 (QA 측정값) | **문서가 코드보다 앞서 달려 서로 어긋남** — 불/전기/쥐 셋 다 다름, 세는 아이 셈 표 둘, D7 자리 +1 셋 (QA 앞뒤 18건) |
| 신 = 규칙, 수첩 뒷장이라는 재도전 축 (review 4) | **규칙을 쌓기만 했다** — 짝수 날 원정, 피로 2가 절대 안 되는 죽은 규칙, 카드가 자리 3칸을 전부 먹는 날 (QA 4·5, normal_game_pass) |
| 사람에게 쌓이는 것(상처·붕괴·기억)의 바탕 (review 3) | **비전 문장이 없었다** — 한 줄 요약은 "장르 넷을 더한 것"이라 충돌 때 기준이 없었다 (framework §0) |

결론: 틀(엔진·아트·말투)은 창고로, **규칙 더미와 열흘 대본은 백지로.**

## 5. 부장 지시서

### 5-1. 기반설계 부장 (세계관·스토리·내러티브·게임 디자인·시스템·레벨·UX)
1. 낸다: 비전 후보 **셋 각각**에 대해 Q1·Q2·Q4 한 장씩(총 3장, 각 30줄) — 디렉터가 고르기 전이므로 셋 다.
2. 각 장은 "핵심 루프 1분·10분·한 판 / 핵심 동사 3 / 실패의 뜻 / 주인공이 원하는 것 / 결말 가짓수"만.
3. 하지 말 것: 수치표, 날짜별 대본, 카드 목록. **[제안] 수치는 한 개도 쓰지 않는다.**
4. 하지 말 것: 프로토타입 규칙(짝수 날 원정, 자리 6, 시선 수지) 인용. 필요하면 "프로토타입에 있었음"이라고만.
5. 맞출 곳: 표현 부장과 **낱말표**(화면에 숫자로 보이는 것·흔적으로 보이는 것) 초안을 같이 쓴다.
6. 맞출 곳: 구현검증 부장에게 "봇으로 잴 수 있는 지표 후보 3"을 넘긴다.
7. 세계·인물은 질문 2의 답이 나오기 전까지 **프로토타입 것을 임시로** 쓴다.
8. 금지: 성폭력·자해 묘사. 식인·죽음은 결과로만, 장면으로 그리지 않는다.

### 5-2. 표현 부장 (아트 디렉터·픽셀/일러스트·UI 아트·사운드)
1. 낸다: 비전 후보 셋에 대한 **톤 보드 한 장씩**(팔레트 5색, 빛의 성격, 화면 한 장 글로 묘사, 참고 이미지는 이름만).
2. 낸다: 기존 자산 약 200점의 **분류표** — 어느 비전에도 쓸 수 있는 것 / 특정 비전만 / 버릴 것.
3. 낸다: 사운드 "0에서 최소"(앰비언트 2, 효과음 5) 목록 — 비전과 무관하게 필요한 것만.
4. 하지 말 것: 새 그림 생산, 규격(타일·초상 크기) 변경 제안. 규격은 Q6 뒤에.
5. 하지 말 것: 세계관·인물 설정 창작. 설정은 기반설계 것을 받아서 그린다.
6. 맞출 곳: 기반설계와 낱말표(위 5-1의 5) — "흔적으로 보이는 것"은 그림이 맡으므로 같이 정한다.
7. 맞출 곳: 구현검증에 파이프라인(Codex → sheet/chunky → manifest) 현재 상태와 11/7 전 범용 자산 후보를 넘긴다.
8. 금지: 성폭력·자해 묘사 그림, 실존 인물·상표 참고.

### 5-3. 구현검증 부장 (프로그래머·툴/파이프라인·QA·검수·텍스트 에디터)
1. 낸다: **창고 목록** — 프로토타입에서 재사용 가능한 것(엔진 dispatch·시드·테스트·봇·탭 걷기·저장)과 각각의 "비전이 바뀌어도 사는가" 판정.
2. 낸다: **기술 제약표** — PC 웹 정적 파일에서 되는 것/안 되는 것(저장·전체화면·음량·폰 가로), 한 장.
3. 낸다: QA·검수 보고에서 **"이전에 틀렸던 것" 체크리스트** 20항 이내 — 새 설계가 같은 함정을 밟는지 재는 데 쓴다(QA 앞뒤 18건, 소프트락 8건에서 추린다).
4. 낸다: 기반설계가 넘긴 지표 후보에 대해 "봇으로 잴 수 있나, 무엇이 더 필요한가" 답.
5. 하지 말 것: 코드 수정, 버그 수정, 리팩터. **프로토타입 버그는 목록만.**
6. 하지 말 것: 설계에 대한 찬반. 검수는 단계 2(교차 검수)에서.
7. 맞출 곳: 텍스트 에디터가 세 부서 문서의 **낱말 통일**(불/전기/시선/노출 같은 혼동어)을 미리 잡아 둔다.
8. 맞출 곳: 표현 부장과 파이프라인·규격 현황 공유.
