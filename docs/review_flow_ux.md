## 1. §1·§2 ✅ 제안 — 조작으로 자연스러운가, 플레이어는 무엇을 보고 떠올리나

| 제안 | 판정 | 지금 코드에서 보이는 것 | 플레이어가 보는 것 → 떠올리는 행동 / 둘 단서 |
|---|---|---|---|
| 1-2 레버 = 즉시 문 | **[동의]** | `prologueObject`: 레버(20,2)를 조사해도 `pro`가 1이 될 뿐 문(21,3)은 `blocked(): t==='o' && pro<2`로 막힌다. 레버와 가방은 `mapObjects()`의 `o.pro < state.pro` 필터 때문에 **하나를 고르면 다른 하나가 지도에서 사라진다** — "양자택일"은 설계가 아니라 이 필터의 부작용 | 레버는 문 바로 옆(20,2)과 (21,3) 사이에 있으니 "레버 → 문"은 이미 공간이 말한다. 당기면 **문 타일이 열린 그림으로 바뀌고 찬 공기 입자(fx)가 문에서 흘러들게** 하면 설명 없이 "나갈 수 있다"가 보인다. 필터를 `pro < state.pro && o.choice != null`이 아니라 '조사한 것만 사라짐'으로 바꿔야 가방이 남는다 |

## 2. 일러스트 — 측정과 레이아웃

### 2-1 §4-1의 수치는 절반만 맞다 **[수정]**
| 창 | §4-1 주장 | 실측 (논리 px, 1280×720에서 ×2) | 실제 문제 |
|---|---|---|---|
| 한 줄(line) + 그림 | 상자 70% = 224, 그림이 꽉 차 글이 아래로 밀려 스크롤 | `#dlg`는 #main(360) 전체를 덮으므로 70% = **252**. 실제 상자 235, scrollHeight 233 → **스크롤 없음** | 스크롤이 아니라 **글이 그림 오른쪽 64px 기둥에 찌그러진다**(prologue·boarding 캡처: "맨 앞 운전실 / 문이 열려 있 / 다."). 원인: `.cg { flex: 0 0 100%; max-width: 384px }` — basis 100%가 max-width 384로 잘려 .lt(64px)와 **한 줄에 들어가 버려** `flex-wrap: wrap`이 발동하지 않는다. 1줄 고침: `.cg { flex-basis: 100% }` 대신 `width:100%`를 떼고 `.box:has(.cg){flex-direction:column}` |

### 2-2 그림 크기 규칙 **[수정]**
- 한 줄 320×180을 **글 옆에** 두면 글 기둥이 456−320−6 = **130px**(9.5px 글자로 13자/줄). 읽을 수 없다. 한 줄 창의 그림은 **글 옆이 아니라 대화창 밖, 무대에** 둬야 한다(아래 A안).
- 선택지 창 256×144를 **왼쪽 위, 글과 나란히**는 된다: 글 기둥 456−256−6 = **194px**(20자/줄), 그림 높이 144 안에 제목+본문 3줄이 든다. 선택지는 그 아래 전체 폭. 합 144+6+118+12 = **280 < 350**, 스크롤 없음.
- 타이틀·결말 384×216: 결말은 명부가 길어 **그림을 무대에, 명부를 상자에**(A안과 같은 방식)로 해야 스크롤이 없다.

### 2-3 레이아웃 비교 (논리 480×360, 1280×720에서 ×2)

**A안 — 그림은 무대에, 글은 대화창에 (한 줄 창·결말·타이틀)** ← 추천
```
┌──────────────────────────────────────────────┐ #stage 480×320
│                                              │
│          ┌────────────────────────┐          │  장면 그림 384×216을 무대 가운데
│          │        장면 그림        │          │  (지도 위에 어두운 막 .35 → 그림)
│          │        384×216         │          │  그림은 '층'이라 다음 줄에도 그대로 남는다
│          └────────────────────────┘          │  같은 키면 다시 그리지 않음 → 깜빡임 없음
├──────────────────────────────────────────────┤
│ [얼굴 96] 이름                                │ #dlg.line 상자 ≈ 110
│           글 한 문장, 전체 폭 350px 36자/줄  ▼ │  (그림 없어도 같은 자리·같은 높이)
└──────────────────────────────────────────────┘
```
- 글 폭 350(36자/줄), 상자 높이가 그림 유무와 상관없이 같다 → 눈이 늘 같은 자리를 본다.
- "같은 그림이 한 줄마다 다시 뜨는" 문제가 구조로 사라진다: `UI.line`이 `o.cg`를 받으면 `#dlg` 안이 아니라 `#stage` 위 `<img id="cgLayer">`에 **src가 다를 때만** 바꾼다. 장면이 끝나면(`playBeats`·`sceneIntro` 끝) 층을 지운다.
- 그림 없는 줄은 지금과 똑같다. 검은 화면(`black`)도 그대로.

**B안 — 그림 고정·글만 스크롤 (상자 안에서)**
```
┌──────────────────────────────────────────────┐
│ ┌────────────────────────┐                   │ 그림 고정(sticky)
│ │  384×216 (또는 320×180) │ 글 기둥 64~130 ↕  │ 글은 좁은 기둥에서 스크롤
│ └────────────────────────┘                   │
└──────────────────────────────────────────────┘
```
- 글 기둥이 좁은 것은 못 고친다. 그림을 위, 글을 아래(세로 쌓기)로 하면 216+글 3줄(46)+▼ = 270 < 252? **안 든다**(상자 상한 252). 320×180이면 180+46+12 = 238로 겨우 든다 — 여유 14px. [반대]

**C안 — 그림을 글 뒤에 흐리게 깔기**
```
┌──────────────────────────────────────────────┐
│░░░░░░ 그림(어둡게 .4) 위에 글 ░░░░░░░░░░░░░░░│
│  제목 / 본문 / 1. 선택지 2. 선택지            │
└──────────────────────────────────────────────┘
```
- 픽셀 그림 위에 9px 명조 글은 가독성이 떨어진다(우리 그림은 밝은 영역이 많다 — ending_safe, open_cab). 글 뒤는 단색이어야 한다. [반대]

**선택지 창(full) — 그림 왼쪽 위 256×144, 글 오른쪽, 선택지 아래**
```
┌──────────────────────────────────────────────┐ #dlg.full 상자 352
│ 저녁 · 약속                                   │
│ ┌──────────────┐ 도현의 열쇠                  │
│ │  256×144     │ 도현이 열쇠를 들고 역에 왔다. │ 글 194px, 20자/줄
│ │              │ "이 열쇠로 지하 통로를…"      │
│ └──────────────┘                              │
│ ▶ 1 부품 3개를 내주고 공동 수리를 약속한다     │ 선택지 전체 폭
│      소모 부품 3 · ⚠ 시선 +1                  │
│   2 며칠만 기다려 달라고 한다                  │
│   3 거절한다                                  │ 합 ≈ 280 < 350
└──────────────────────────────────────────────┘
```
- 지금 `cgImg()`가 `<img class="cg">`를 본문 위에 끼워 넣는다 → `.full .box` 상단을 `display:grid; grid-template-columns: 256px 1fr`로, `.opts`는 `grid-column: 1/-1`.

### 2-4 그림이 매 줄 다시 뜨는 문제 **[동의, 방법 수정]**
- 지금: `sceneIntro`·`playBeats`는 **첫 문장에만** cg를 넘긴다 → 둘째 문장부터 그림이 **사라진다**(반복이 아니라 소멸). 사용자가 "스크롤" 다음으로 귀찮다고 느낀 것은 아마 "문장마다 상자 모양이 바뀌는 것"이다.
- A안의 그림 층이면 "유지"가 기본값이 되고, 바꿀 때만 바뀐다.

## 3. 누르기·걷기 수 어림 (data.js 문장 수 × `splitSentences` 규칙으로 셈)

## 5. 발견 순서(사람이 하루씩 늘어남)를 화면에 어떻게

| 요소 | 제안 | 근거 |
|---|---|---|
| 패널 사람 수 | 패널에 **사람 수를 숫자로 두지 않는다.** 대신 수첩(Tab) 명부에 **발견한 사람만** 줄이 생기고, 빈 줄은 "……"로 남는다 — 명부가 "일곱 자리 중 두 자리"임을 스스로 보인다 | 지금 HUD는 식량·물·부품·약품·침수·노출뿐(사람 수 없음). 숫자를 더하면 "아직 N명 더"가 **목표**가 되어 발견이 과제로 바뀐다. 가시성은 명부가 맡는다 |
| 지도의 '아직 없는 사람' 흔적 | 은지·동하: 지하상가 통로 출구(0,6) 셔터 안쪽에서 **두드리는 소리 + 셔터 틈 빛 깜빡임**(lights에 간헐 등록). 서하: 역무실 문(15,2) 틈으로 **푸른 휴대폰 빛**(lights, 색 다르게) + 호버 "역무실 문 — 안에서 빛이 샌다". 기철: D0에 지나쳤으면 D1 아침 터널 쪽에서 **헤드램프가 걸어 들어온다**(walkers). 마리: 승강장 끝 잠자리에 **앉아 있는 스프라이트**(눕기 스프라이트는 있음, 앉기는 저녁 그림 9장과 함께) | 빛·소리·사람 — study_map_story §3-2 3. 전부 지금 엔진에 있는 수단(lights·walkers·hoverName)으로 된다. "불 꺼진 잠자리"는 **이미 6개가 다 비어 보여서** 흔적이 안 된다 — 잠자리는 사람이 늘면 담요가 **깔리는** 쪽이 낫다 |
| 발견 순간 연출 | **카드도 종도 아니고, 한 줄 대화 + 명부 토스트.** 셔터를 열면 두 사람이 **걸어 들어와** 순례 옆에 서고, 은지의 한 줄("문 두드린 지 한참이에요"), 그리고 토스트 "명부에 두 줄 — Tab". 카드(FX.card)는 날짜·막 전환에만 쓴다 | 카드는 '장이 바뀜'의 신호라 사람 하나에 쓰면 값이 떨어진다. 종(FX.blip)은 피격·징조에 쓰고 있어 섞이면 안 된다. "수첩에 줄이 는다"는 이 게임의 핵심 물건(명부)과 묶인다 |
| 아침 일손 수 | 게시판 '오늘' 탭의 사람 칩이 **2 → 4 → 6개로 늘어나는 것**이 곧 가시성. 빈 칩 자리는 두지 않는다 | `boardFlow`의 `plan` 칩은 `status==='home'`만 그리므로 엔진에 `away`를 넣으면 **코드 변경 없이** 된다 |
| 발견 전 '예산' 경고 | D0~D1에 식량·물이 2명 기준으로 넉넉해 보이다가 D2에 6명이 되면 급격히 줄어든다 — 게시판 '내일 아침 예상'의 delta가 이미 이를 보여 준다. 셔터를 열 때 **"들이면 입이 둘 는다"를 부제로** | 두 자원 규칙(사람 ↔ 식량). 안 열어도 D2에 순례가 연다 — 선택의 값은 하루치 식량과 신뢰 |
