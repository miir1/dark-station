# 회의 2라운드 — 구현·검증 부장 답변 (2026-10-21)

대상: issues.md 쟁점 3·5·6·8. 코드는 v3/game.js(loop·__ds3)·ui.js(타자)·fx.js(card)·v2/engine.js(normalize)를 읽기만 했다.

## 쟁점 3 — 정체 축 값 저장과 테스트 틀: **절충안 수용**
- 저장: `state.axes = { share: 0, hand: 0, name: 0 }` 정수 −9~+9. 표시 없음. 봇·테스트만 읽는다. 결정 입력은 사건표 열 `axis: { share: +1 }`로만 — 코드가 축을 직접 더하지 않는다.
- 결정표: `data/identity.json` = 8칸(각 축 부호 조합) → 정체 id. 0은 "그 축 기울지 않음"으로 부호를 따로 두면 27칸이 되므로, **0은 결정표가 지정한 쪽**으로 묶는다(표 열 `zeroAs`).
- 테스트 틀 1줄: `identity(axes)`는 순수 함수 → ① 8칸 전부 정체 id가 있고 4종 모두 ≥1칸 ② 봇 정책 4~6 × 200판에서 정체 4 각 ≥ 10% ③ 같은 시드·같은 선택이면 같은 정체(결정성).

## 쟁점 5 — 흔적 상태·봇 조사 규칙·발견율 측정: **절충안 수용, 흔적은 "저장"**
- 흔적 상태는 **저장에 둔다**(`state.traces = { 물건id: { st, day, by } }`). 재계산은 밤 사건 난수를 아침에 다시 굴려야 해 결정성이 깨지고, "조사한 뒤 지워진 흔적"을 표현할 수 없다. 소품 수는 두 배가 아니다: 물건 1 + 상태 덧그림(빈/옮겨짐/피) 1~2 = 지도 소품 약 12종 × 상태 2 = **덧그림 20장 내외**, 소품 자체는 늘지 않는다.
- 봇 아침 조사 규칙 2종(기반설계가 판단 정보 목록으로 다듬되, 측정 정의는 이렇게):
  - **부지런**: 아침 흔적 단계에서 조사 가능한 곳(3~5)을 전부 조사하고, 소문이 가리킨 사람에게 말을 건다.
  - **게으름**: 시작 칸에서 가장 가까운 곳 1곳만 조사하고 배식으로 넘어간다. 말은 안 건다.
- "발견 50~70%"는 **balanced(=부지런과 게으름의 중간: 가까운 2곳 + 소문 1건)** 봇 하나로 재고, 부지런·게으름은 상·하한 보고용. 발견 = 그 사건이 남긴 흔적·소문 중 하나라도 봇이 조사/들음. 합격선 "끝까지 모르는 ≥1"은 게으름 봇 기준, 찬가 발견율 ≥70%(쟁점 7)는 부지런 봇 기준.

## 쟁점 6 — 0배속 화면 완주 구현법: **절충안 수용**
- 지금 구조: 걷기는 `STEP_MS = 230`을 `frameDt`로 나눠 진행(`loop`가 rAF), 타자는 `ui.js` `setInterval 18ms`, 장 전환은 `fx.js card()` `setTimeout 1400+700`, 입자는 draw마다. 디버그 훅 `window.__ds3`(localhost 전용)에 `act·flow·step·frame·interact·walkTo·target`이 이미 노출되어 있다.
- 구현: `?fast=1`(localhost만) → ① `STEP_MS` 1 ② 타자 간격 0 + 열리자마자 전체 글 ③ `card` 지연 0 ④ 입자·알갱이·안개 끔 ⑤ rAF 대신 `__ds3.frame()`을 스크립트가 호출. 플레이스루 스크립트(헤드리스 크롬, `tools/playthrough.js`): `__ds3.state`를 읽어 phase별로 "조사물로 walkTo → interact → 대화창 첫 선택지(1번 키)"를 반복, 콘솔 오류·30초 무진행(막힘)을 실패로. 선택은 엔진 봇의 balanced 규칙을 같은 파일에서 재사용(화면용 어댑터).
- 어림 소요: fast 스위치 **소**(코드 5곳, 반나절), 플레이스루 스크립트 **중**(2~3일, 새 화면 흐름이 잡힌 뒤). 완주 1회 ≈ 5~10분. 합격선 "하루 결정 ≥5"는 엔진 봇이 dispatch 횟수로, "망설임 중앙값 ≥3초인 날 ≥7/10"은 사람 플레이 때 `localStorage`에 선택지 열림→고름 시간을 적는 로그 10줄로.

## 쟁점 8 — 직전 턴 사본: **절충안 수용**
- 키: 현재 `darkstation.v3.save` 하나 → 새 밑바탕은 `ds.save`(현재) + **`ds.save.prev`**(직전 아침 시점 사본). prev는 **아침(배식 전) 진입 때만** 갱신 — 턴마다가 아니라 하루에 1번. 플레이어 메뉴에 노출 없음.
- 복구 조건(load 순서): ① `ds.save`가 JSON 파싱 실패 또는 `normalize`가 null(버전·phase 불일치) → ② `ds.save.prev` 시도 → 성공이면 토스트 한 줄 "저장이 깨져 직전 아침으로 돌아갔다" + 그 사본을 `ds.save`로 다시 씀 → ③ 둘 다 실패면 새 게임 + 깨진 원본을 `ds.save.broken`에 보관(버그 보고용, 다음 정상 저장 때 지움).
- 마이그레이션: `normalize`가 `v`를 보고 `migrate[v→v+1]` 체인을 돌린 뒤 검사. 저장 포맷 변경 커밋은 반드시 마이그레이션 테스트(옛 fixture 1장 → 새 버전 로드 성공) 동반.
