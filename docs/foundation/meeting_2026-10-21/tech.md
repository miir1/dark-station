# 부서장 회의 1라운드 — 구현·검증 부장 발언 (2026-10-21)

대상: 11_design_v2.md · 02_vision_study.md(E1~E10) · 03_director_decisions.md 결정 기록(적나라·전투 있음·1시간 이상·숨은 정체). 입장만, 결정 아님.

## 1. 찬성 — 구현이 쉬워지거나 검증이 또렷해진 것
| # | 항목 | 왜 좋은가 |
|---|---|---|
| 1 | **신 수치·시선·신뢰 표시 폐기, 세계 시계(날짜·안개 칸·수위·땔감)만** | 상태 필드가 40개 → 절반 이하. 밤 사건 조건이 "시계 + 욕구"뿐이라 표 한 장으로 적히고, 봇도 같은 입력만 보면 된다 |
| 2 | **"당신이 어디 있었든 조건이 아니다"(E1·E9)** | 주민 간 사건을 플레이어 입력 없이 굴릴 수 있다 = Node에서 밤만 1,000번 돌리는 단위 테스트가 가능. 흔적/소문 두 출력은 그대로 자동 검사 대상 |
| 3 | **고정 장면 D3·5·7·9 + 매일 시험 1개 + 결말 = 명부 한 장** | 고정 장면은 fixture 1장씩으로 캡처·문장 검사가 된다. 결말이 명부 1장이면 "결말 출력 = 상태의 순수 함수"로 테스트가 한 줄 |

## 2. 반대·우려
| # | 제목 | 근거 | 대안 |
|---|---|---|---|
| U1 | **쌍별 밤 사건 표의 작업량** | 주민 6 → 쌍 15 × 조건(욕구 4 문턱·시계)별 사건. 쌍마다 2개만 써도 30개 사건, 각각 글·흔적·소문 셋 = 글 90줄 이상. 데이터 표의 지금 사건 수(약 40)와 맞먹고, 발생 조건이 겹치면 봇이 같은 사건만 6번 굴린다 | 쌍별이 아니라 **역할별**(훔치는 쪽/빼앗기는 쪽)로 사건 12개 + 쌍 고유 사건 5개(장면 5의 인물)로 줄인다. 합격선 "사건 ≥ 6"은 잴 수 있다(상태 로그에 사건 id). "발견 50~70%"는 **봇이 아침에 조사할 곳을 고르는 규칙**을 먼저 정해야 잰다 — 규칙이 없으면 숫자가 봇 정책의 산물이지 설계의 산물이 아니다. "끝까지 모르는 ≥ 1"은 잴 수 있으나 봇이 전부 조사하는 정책 하나로는 항상 0 — 정책 2종(부지런/게으름)의 범위로 보고해야 한다 |
| U2 | **숨은 정체 축 3이 테스트 가능한가** | 축 3 × 양쪽 = 조합 8인데 정체는 4 — 나머지 4 조합이 어디로 가는지 표가 없다. "네 정체 모두 도달 가능"은 봇으로 **증명 가능**: 정책 4종(몫 내줌+개입 / 챙김+적기 / 적기+침묵 / 부름+챙김)을 200판 돌려 각 정체 ≥ 60% 나와야 함. 문제는 축이 "쌓인다"의 문턱값이 없다는 것 | 축 값을 −N~+N 정수로 저장(표시 없음, 저장에만), 정체 결정표를 **8칸 전부** 채워 달라. 그러면 테스트는 "결정표 함수 × 봇 정책 4"로 한 파일 |
| U3 | **85분 한 판 자동 플레이스루** | 헤드리스 크롬 실시간 85분은 못 돌린다(검증 1회에 1.5시간). 봇은 엔진만 돌려 2초지만 "화면이 85분을 채우나"는 못 본다 | 둘로 나눈다. ① 엔진 봇 = 규칙·합격선(초 단위). ② 화면 플레이스루는 **연출 시간 0배속 스위치**(`?fast=1`: 걷기 즉시·카드 0ms·입자 끔)로 10분 안에 완주, 콘솔 오류·막힘만 본다. "85분이 맞나"는 사람 플레이테스트 1회 + 결정 횟수(하루 ≥ 5)를 봇이 센다 |
| U4 | **영구 손상 5종의 분기 수** | 손가락(자물쇠)·눈(글 가림)·다리(걸음·도보 결말)·이(말)·귀(D7 대답 확률). 각각 던전 선택지 조건 · 원정 글 · 결말 분기에 닿는다. 사람 7(당신 포함) × 5종 × 닿는 곳 3 = 조건 분기 100곳 이상. 그중 '글 일부를 "…"로 가림'은 문장 검사가 못 잡는다(가려진 글이 길이 검사를 통과) | 손상은 전부 **기술 수치 −1 + 조건 깃발 1개**로만 표현하고, 분기는 "깃발이 있으면 선택지가 잠긴다/열린다" 한 종류로 제한. 글 가림은 렌더 단계(화면)에서 하고 데이터는 손대지 않는다 |
| U5 | **되감기 없음 + 자동 저장 하나 + 당신 사망** | 기술로는 가장 쉽다(지금 구조 그대로). 우려는 **저장 깨짐 = 85분 손실**. 지금 `normalize`는 깨진 저장을 **새 게임**으로 보낸다 — 되감기 없는 게임에서 그건 "버그로 죽음"이다. 당신 사망 결말(수첩을 주운 주민이 읽음)은 분기가 아니라 **읽는 사람 1칸**이라 쉽다 | 자동 저장은 하나지만 **직전 턴 사본 1개**를 내부에 둔다(플레이어는 못 돌림, 저장 깨짐 때만 복구). 저장 포맷 변경 시 마이그레이션 함수 필수. 당신 사망은 `phase: 'ended', reader: 'you'|'conductor'|'resident'`로 끝 |

## 3. "표 여섯 장"이 v2를 담는가
담기는 것: 페이즈표(하루 7단계) · 자원표(식량·물·땔감 + 당신) · 사건표(원정·시험·고정 장면) · 인물표 · 지도 · 대사표.
**모자라는 것 3장** → 아홉 장으로 늘린다:
| 추가 표 | 내용 |
|---|---|
| **밤 사건표** | 조건(욕구 문턱·시계) → 행위자/대상 → 흔적(물건 id·상태) + 소문(목격자·문장·참/거짓) |
| **흔적·물건표** | 지도 위 물건 id별 상태(빈/찬/옮겨짐/피)와 조사 글. 아침 흔적의 재료 |
| **정체 결정표** | 축 3 값 범위 8칸 → 정체 4 + 호칭·꿈·유리창 글 단계 |
인물표에는 열 추가: 욕구 4, 비밀 깃발, 악의 조건, 찬가 조건. 영구 손상은 자원표의 '몸' 항목으로.

## 4. 수직 슬라이스 범위 제안
**D0~D3** (프롤로그 + 물통 장면 D2 + 셈 "+1" D3). 근거: ① 밤 사건 체계(U1)·흔적 조사·배식 그릇이 D1~D2에 전부 등장 ② D3 셈은 "당신도 세어진다"(E7)의 첫 시험 — 가장 위험한 설계 가정을 가장 먼저 본다 ③ 전투는 D0~D3에 0~1회라 battle 틀만 붙이면 됨 ④ 정체 축은 D3까지 움직이되 결말은 안 넣는다(결정표가 8칸 채워진 뒤).
D0~D5까지 가면 식인 장면(수위 규격 미정)과 범람·도현 분기가 들어와 작업량이 두 배가 된다.
어림: **중**(해석기 + 표 9장 뼈대 + 화면 D0~D3 + 봇 2정책). D0~D5는 **대**.

## 5. 다른 부장에게
- **기반설계 부장**: 정체 결정표 8칸을 전부 채울 수 있나, 아니면 축을 2개로 줄여 4칸=정체 4로 맞추는 쪽이 설계상 더 정직한가.
- **표현 부장**: 자세 스프라이트 6인×4 [제안]과 흔적 그림(빈 물통·피 베개 등)이 Codex 기한(11/7) 안에 나오나 — 안 나오면 화면은 어떤 **글자/색 대체**를 허용하나.
