# 어두운 역 — 아트 디렉션 재설계 (2026-10-20)

출발점: "사람들 인게임 그래픽이나 소모품 같은 것도 너무 커, 픽셀 던전 느낌이 너무 강하게 나." (brief.md)
그림을 직접 보고(v3/img), 크기를 코드에서 재고(art3.js·game.js), 변환 파이프라인(tools/)을 읽은 뒤 쓴다.
지도의 모양·칸 수는 level.md가 맡는다. 여기서는 **칸 크기와 한 화면에 몇 칸 보이나**까지만.

---

## 1. 지금 그림의 진단 — 무엇이 '픽셀 던전'처럼 보이게 하나

재는 법: art3.js 297행 `S = 3, TT = 48, PH = 72`, game.js 236행 `resize()`의 `scale = min(4, 무대높이/(48×13), 무대너비/(48×7))`. 폰 390×844(무대 약 390×680)에 넣으면 배율 ≈ 1.09.

| 항목 | 지금 수치 (폰 390×844 기준) | 왜 '던전 탐험기'로 보이나 |
|---|---|---|
| 타일 | 48px 원본 × 1.09 ≈ **52px** | RPG Maker VX/Ace(32px)보다 1.6배. 바닥 한 칸이 손톱만 하다 |
| 한 화면 칸 수 | 가로 **7.4칸** × 세로 13칸 | Pixel Dungeon도 가로 7~9칸. 쯔꾸르는 가로 11~17칸. 칸이 적으면 '방'이 아니라 '복도 한 토막'만 보인다 |
| 사람 | 48×72 원본 → 화면 **52×78px**, 무대 높이의 1/8.7, 타일의 1.5배 높이 | 비율(6등신)은 좋다. 문제는 절대 크기 — 폰에서 사람 하나가 엄지손가락만 하다 |
| 소품 | 전부 48×48 한 칸 꽉 채움 (드럼통·게시판·구두까지 같은 크기) | 구두(heel.png)가 드럼통과 같은 크기. 크기 위계가 없어 '아이템 칸'처럼 읽힌다 |
| 외곽선 | 사람·소품·크리처 전부 1px 순검정(#050404) 테두리 (sheet.py `outline`) | Pixel Dungeon의 가장 강한 특징이 '검은 테두리 스프라이트'다 |
| 어둠 | 주변 암흑 0.55(낮)~0.86(밤) + 주인공 반경 2.4칸 빛 + 가장자리 비네트 0.75 + 알갱이 40점/프레임 | 좁은 화면에 둥근 빛 하나 = 로그라이크 시야(FOV)처럼 보인다 |
| 초상 | 128px 원본(64도트×2) → 대화창에 112px | 도트 굵기 1.75px. 지도는 1.09px, 장면 그림은 1.6px — **세 가지 도트 굵기가 한 화면에 섞인다** |
| 장면 그림 | 480×270 → 폰 폭 390 (0.81배 축소) | 축소되며 도트가 뭉개진다. 그림 자체는 좋다 |
| 아이콘 | 40px | 좋다 (사용자 선호) |

**지킬 것 (좋다, 버리지 않는다)**
- Codex 원본의 분위기: 초상(soonrye.png)의 표정과 조명, 장면 그림(open_camp·story_ticket)의 구도와 빛. 그림체 자체는 목표(Fear & Hunger)에 이미 가깝다.
- 사람 비율 6등신, 걷기 4방향×3프레임 구조, 옷 색으로 사람을 구별하는 방식.
- 팔레트의 방향(잿빛·뼈색·마른 피·녹슨 금·탁한 청록). 수는 줄인다.
- 색 있는 빛(비상등 빨강, 휴대폰 푸른 기, 드럼통 주황) — 이건 쯔꾸르 호러의 핵심 장치다.
- 아이콘 UI, 분홍 바탕 시트 → 파이썬 자르기 파이프라인(자산 원본 art_src/는 전부 고해상도라 **다시 자르기만 하면 된다**).

## 2. 새 방향 2~3안 비교

### A안 '정통 쯔꾸르' — 지도를 쯔꾸르 크기로 되돌린다
- 타일 32px, 사람 1칸 너비 × 1.5칸 높이, 폰 가로 **12칸**, 비네트 약하게.
- 참고작: Fear & Hunger 1·2(48px 타일이지만 PC 17×13칸), RPG Maker 호러(Ib, 마녀의 집, Ao Oni), 「OMORI」의 어두운 구간.
- 폰 세로 구성도:
  ```
  ┌──────────────┐ 0~40      상태줄 (날짜·시간·자원 아이콘)
  │              │ 40~720    지도 12칸×21칸 (32px). 사람 32×48
  │   지도       │           대화가 뜨면 아래 1/3을 덮는다
  │              │
  ├──────────────┤ 720~844   십자키 + 조사/메뉴 (지금과 같음)
  └──────────────┘
  ```
- 장점: 사용자의 불만을 정면으로 푼다. 자산은 다시 자르기만. 코드 변경이 수치 몇 개.
- 단점: 세로 21칸이 보이므로 지도가 '넓고 비어' 보일 수 있다 → level.md에서 지도를 가로로 길게, 세로 10~14칸으로.

### B안 '장면 중심' — 걷는 지도는 작게, 사건·대화는 장면 그림 + 초상이 주인공
- 지도는 화면 위 절반(32px, 12×10칸)만. 아래 절반은 항상 '장면 창'(장면 그림 16:9 또는 초상 + 글).
- 참고작: 서울 2033(사건 카드), Darkest Dungeon(지도 위·장면 아래), 「도시의 한 사람으로 태어나」, Sunless Sea.
- 폰 세로 구성도:
  ```
  ┌──────────────┐ 0~40      상태줄
  │   지도 12×10 │ 40~360    걷는 지도 (작게)
  ├──────────────┤
  │  장면 그림   │ 360~580   16:9 그림 또는 초상 96 + 이름
  │  글·선택지   │ 580~760   글 17px, 선택지 2~4
  ├──────────────┤ 760~844   십자키/조사
  └──────────────┘
  ```
- 장점: 장면 그림 67장이 늘 보여 '이야기 게임' 느낌이 가장 강하다. 글 중심(A Dark Room) 톤과도 맞다.
- 단점: 지도가 10칸 높이뿐이라 걷는 재미가 줄고, 장면 그림이 없는 순간엔 아래 절반이 빈다(장면 그림을 100장 넘게 더 만들어야 함, Codex 11/7 마감).

### C안 '옆에서 본 역' — 횡스크롤 한 줄 승강장 (Blasphemous·Darkest Dungeon 보행 구간)
- 지도를 격자 대신 '옆모습 한 줄'로. 사람 64×96, 배경 3겹(먼 벽·기둥·앞 바닥).
- 참고작: Darkest Dungeon 복도, Blasphemous, 「Kentucky Route Zero」.
- 장점: 그림체(Blasphemous)에 가장 잘 어울리고 사람이 커도 어색하지 않다.
- 단점: 지도·엔진(maps.js, 4방향 걷기, 150장 걷기 그림)을 전부 버린다. 재설계가 아니라 새 게임이다.

### 추천: **A안을 뼈대로, B안의 '장면 창'을 사건 때만 끌어온다** (A+B)
이유: (1) 불만의 원인(크기·칸 수·테두리·비네트)을 전부 수치로 고칠 수 있고, (2) 원본 그림을 다시 자르기만 하므로 11/7 전까지 Codex는 '새 것'에만 쓸 수 있으며, (3) 사건·대화가 열릴 때 B안의 아래 절반(장면 그림+초상+글)을 덮어 쓰면 '이야기 게임' 느낌은 B안만큼 난다. C안은 다음 막(2막) 후보로 남긴다.

## 3. 추천안의 수치 스펙 (폰 390×844 기준)

**원칙 하나: 한 도트 = 화면 1px(CSS).** 지도·초상·장면·아이콘이 같은 굵기의 도트를 갖는다. (지금은 1.09 / 1.75 / 1.6 / 1px이 섞여 있다.)

| 항목 | 지금 | 새 스펙 | 비고 |
|---|---|---|---|
| 타일 | 48px | **32×32** | 배율 1.0 (390/384). 큰 폰(430)도 1.0 유지하고 칸을 더 보여준다 |
| 화면 배율 | 1.09~4 (소수 허용) | **1.0 고정**, 태블릿·PC만 2.0 | `scale = W >= 768 ? 2 : 1` |
| 한 화면 칸 수 | 7.4×13 | **12.2 × 21** (지도가 작으면 가운데 정렬) | 세로가 남으면 상태줄·메시지 띠로 쓴다 → level.md |
| 사람 | 48×72 (1.5칸 높이) | **32×48** (1칸 너비, 1.5칸 높이) | 머리가 윗칸에 16px 걸친다. 6등신 유지 |
| 소품(바닥 1칸) | 48×48 전부 | **32×32** 기본 + **32×64 (기둥·자판기·문·계단)** + **16~24 (구두·전화·약상자: 칸 안에 작게, 바닥 정렬)** | 크기 위계를 만든다 |
| 크리처(전투창) | 96×96 | **128×128** [제안] | 전투창은 지도가 아니라 '장면'이므로 크게. 원본 시트가 고해상도라 가능 |
| 초상 | 128 → 112 표시 | **96×96 원본, 96 표시** | 대화창 왼쪽. 다친 얼굴도 같은 크기 |
| 장면 그림 | 480×270 → 390 축소 | **384×216 (16:9) 원본, 폭 100% 표시** | 390 폰에서 1.016배 — 도트가 안 뭉개진다. 큰 폰은 가운데 정렬·양옆 검정 |
| 아이콘 | 40 | **40 유지** (상태줄은 24로 축소본 하나 더) | 사용자가 좋아함 |
| 글자 | 대화 19 / 본문 18 / 보조 16 | **대화 17 / 본문 17 / 보조 15 / 선택지 17** [제안] | 그림이 작아지니 글자도 한 단계 줄여 균형. 15 밑으로는 안 내려간다 |
| 팔레트 | 24줄×3단 = 72색 | **총 32색**: 잿빛 6, 뼈색 4, 피 3, 녹슨 금 3, 청록 3, 피부 3, 머리카락 3, 녹색(2호선) 2, 보라-안개 2, 검정/잉크 3 | 주조색: 잿빛 바닥 + 뼈색 빛 + 피/금 강조 |
| 외곽선 | 1px 순검정 전부 | **사람·크리처: 1px, 그 물체의 가장 어두운 색**(검정 아님). **서 있는 소품: 아래쪽만 1px 그림자**. **바닥에 깔린 것(핏자국·웅덩이·종이)·타일: 없음** | 검은 테두리가 '픽셀 던전'의 절반이다 |
| 어둠(주변) | 낮 0.55 / 밤 0.86 | **낮 0.40 / 밤 0.70 / 터널 0.85** | 화면이 넓어졌으니 덜 가려도 무섭다 |
| 빛 반경 | 주인공 2.4칸, 드럼통 4.8칸 | **주인공 3.5칸, 드럼통 6칸, 램프 5칸** (칸 단위라 K 보정 그대로) | 둥근 빛 하나가 화면 1/3 이상이면 FOV로 안 읽힌다 |
| 비네트 | 가장자리 0.75 | **0.35**, 시작 반경 0.45 | |
| 알갱이 | 40점/프레임 | **12점**, 대신 **안개 겹** 한 장(64×64 반복, 알파 0.08, 초당 4px 흐름) | 안개는 세계관 장치(잿빛 안개)와 맞는다 |
| 그림체(사람) | 6등신, 눈 2도트 | **6등신 유지. 머리 8×8도트(폭×높이), 눈 1도트 2개, 입 없음.** 옷 색 2단(바탕+그늘)+강조 1색 | 표정은 초상이 맡는다 |
| 그림체(초상) | 64도트 | **96도트, 색 24~28, 조명 한 방향(아래-왼쪽 불빛)** | 원본 그대로, 작게 자르기만 |

재는 법(검증): 바꾼 뒤 폰에서 캡처해 주인공 높이 ÷ 무대 높이 = **1/14** 근처(지금 1/8.7)이면 통과. 가로 칸 수는 캡처 폭 ÷ 32.

## 5. 파이프라인 변경 (tools/)

| 파일 | 지금 | 바꿀 것 |
|---|---|---|
| **sheet.py** `fit()` | 모든 덩어리를 같은 W×H에 맞춤, 테두리 1px 순검정 `OUT=(5,4,4)` | ① 이름에 크기를 붙여 받기: `drum,heel:20x20,pillar:32x64` (없으면 기본 W×H). ② `outline(im, color=None)`: color가 없으면 그 그림의 가장 어두운 색(알파 있는 픽셀 중 밝기 최소)으로. ③ `--no-outline` 옵션(바닥 장식용). ④ `run_tiles --size 32` |

## 6. UI 방향 (대화창·선택지·게시판·전투)

1. **창은 지도 위에 '덮는' 검은 판** — 지금의 2px 뼈색 테두리(#8a7d66)와 안쪽 2px 그림자 유지. 둥근 모서리 없음, 반투명 없음(판 자체는 불투명 #15130f, 바깥 지도만 35% 어둡게).
2. **대화창 = 초상 96 왼쪽 + 이름(금색 14px 자간 넓게) + 글 17px 세리프 한 줄씩 타자**. 장면 그림이 있으면 창 위에 384×216 가득, 글은 그 아래. 초상과 그림이 같이 있으면 초상은 그림 위 왼쪽 아래 모서리에 겹친다.
3. **선택지는 세로 목록, 한 줄에 '행동 — 대가'**: 아이콘 24 + 글 17 + 회색 15 보조(비용·확률). 판단 정보는 다 보여 준다(brief 원칙 6). 고를 수 없는 것도 회색으로 보이게.
4. **게시판·일지·상태 창은 '종이'가 아니라 '벽'**: 같은 검은 판에 아이콘 40 격자. 아이콘 UI는 지금 그대로. 종이 질감·손글씨 폰트 안 쓴다(쯔꾸르 호러의 흔한 함정).
5. **전투 창은 장면이다**: 위 2/3에 크리처 128을 어두운 바닥 위에, 빛은 아래-왼쪽 하나. 부위(머리·몸·팔·다리) 4칸은 아이콘 24로 크리처 밑에 가로 한 줄. 피는 글이 아니라 크리처 그림 위에 덧칠(지금 person2의 `hurt` 방식 재사용).

## 7. 한 장면 목업 — 승강장 아침 (폰 390×844, 배율 1.0)

```
y 0~40    상태줄: [D3 아침] 24px 아이콘 6개(식량·물·약·부품·전력·신뢰) + 숫자 14px, 오른쪽 끝 '남은 시간' 금색
y 40~720  지도 (무대 390×680 = 12.2×21.25칸, 32px 격자)
y 720~844 십자키(왼쪽 110×110) · 조사/메뉴(오른쪽 2개, 72×44)
```
지도 안(무대 왼쪽 위를 0,0으로):
- 바닥: 승강장 타일 32px, 잿빛 2단. 세로 3칸(y 96~192)이 노란 점자블록 띠(새 타일, 외곽선 없음). 그 아래(y 192~224) 선로 턱, y 224~288 선로 2칸(어두운 자갈 + 녹슨 레일 1도트 선).
- 바닥 장식: 핏자국 1장(x 64, y 128), 종이 뭉치 2장, 금 간 타일 3장 — 외곽선 없이 깔려 '그림'처럼 보인다.
- 기둥 2개 32×64 (x 96, y 32~96 / x 288, y 32~96): 2칸 높이라 천장이 있는 느낌이 난다. 뒤 벽(y 0~32) 흰 타일 + 2호선 녹색 띠 1칸.
- 드럼통 32×32 (x 192, y 160): 불꽃 3프레임 16×16이 위에 겹침. 빛 반경 6칸(192px) 주황 0.22 → 화면 가운데 절반이 따뜻하고 가장자리는 잿빛.
- 사람 32×48: 순례(x 160, y 144, 앉은 자세는 없으니 선 채로 드럼통 왼쪽), 서하(x 224, y 176, 아래 보기), 기철(x 320, y 64, 기둥 옆 등 보이기), 주인공(x 192, y 208, 선로 턱 위 — 머리 16px가 윗칸에 걸침). 사람 높이 48 = 무대의 1/14. 네 사람이 한 눈에 들어오고 서로의 거리(3~4칸)가 읽힌다.
- 머리 위 반응: 서하 위에 '…' 16×16 (x 232, y 160).
- 어둠: 낮 0.40. 드럼통·램프(x 352, y 32, 반경 5칸) 두 빛. 비네트 0.35 — 화면 모서리만 살짝 가라앉는다. 안개 겹 0.08이 오른쪽에서 왼쪽으로 느리게 흐른다.
- 오른쪽 끝(x 352~390)은 지도 밖 검정이 아니라 다음 칸이 1.2칸 보인다(12.2칸) — 통로가 이어진다는 느낌.

대화가 열리면(서하에게 '조사'): y 420~720에 검은 판. 왼쪽 초상 96(서하, 다치지 않은 얼굴), 이름 '윤서하' 금색 14px, 글 17px 3줄, 그 아래 선택지 2개(아이콘 24 + 글 17 + 보조 15). 지도 위 2/3은 35% 어두워진 채 그대로 보여서 '어디서 말하고 있는지'가 유지된다.

지금과의 차이를 한 줄로: **같은 화면에 보이는 사람이 1~2명 → 4명, 칸이 7 → 12, 검은 테두리 → 색 테두리, 둥근 시야 → 넓은 어둠과 두 개의 빛.**
