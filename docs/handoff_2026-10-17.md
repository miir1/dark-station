## 2. Astra 플레이 테스트 결과 (범위: 400px, 프롤로그~D4 착공 확인창)
Astra 제안 목표: **"플레이어가 규칙을 이해한 상태에서, 무엇을 포기할지 고민하게 만들기."** 지적 요지:
1. 준비물이 있으면 확정 성공 → 고민이 끝난다. 안전한 해결에도 포기할 것, 위험한 해결에도 별도 이득이 있어야 한다(핵심 사건 몇 개만). 성공 시 이득도 실패 위험만큼 명확히.
2. **공사 단계가 모두 "시작"이라 혼란**(D3 "공동 수리를 시작한다" → D4 "진행 중인 공사 없음" → 별도 착공). "재료 없음", "부품 없음을(를) 내고" 문구.
3. 10일이 매일 다른 판단을 만들어야 한다. 구간별 역할 제안(D1~2 학습·첫 구조 / D3~4 투자 / D5 예고된 범람으로 준비 확인 / D6~7 복구·인물 요구 / D8~9 부족분 확정 / D10 결과). **D5 범람에서 대비한 만큼 결과 차이가 분명해야.**
4. 부품의 경쟁(통로·시설·들것)은 유망하지만 비교가 어렵다 → 건설 버튼에 남는 부품·작업량·인원/전력·들것 변화 표시. "비상 해체 6→4→2" 단위 불명확.
5. 약국: "문이 안 열려요"(고장)인데 약을 건네면 안에서 빗장을 엶(불신) → 인과 불일치. 주민 바람을 실제 결정에 연결(동행자에 따라 한 문장·한 선택지부터). 대화 3회 = 능력 보상만 강조하면 강화 버튼처럼 느껴짐 → "어제 한 일을 기억한다"는 반응 먼저.
6. 모바일: 정보가 흩어져 있음 → 하루 종료 버튼 근처에 예상 결과. 추천 배치에 짧은 이유("물 확보 우선").
7. 그래픽은 상태·결과를 보여주는 데 투자(침수에 잠기는 계단·시설, 공사 진척, 열차 준비되는 승강장). 장면 그림은 첫 구조·범람·열차 도착에만.
